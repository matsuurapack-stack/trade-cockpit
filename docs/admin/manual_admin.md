# トレード・コックピット 管理者マニュアル（管理者専用）

このファイルは管理者（あなた）専用です。**利用者には渡さないでください。**
パスワード・URLの実値は、このファイルにも Git にも書かないでください（紙またはパスワード管理アプリで保管）。

---

## 0. 仕組みの全体像

- ログイン方式：**ユーザー名＋パスワードのログイン画面**（Cookieのセッション）。旧Basic認証は廃止しました。
- パスワードは**ハッシュ化**してDB（`app_users`）に保存します。平文はどこにも保存されません。
- ログインすると、**サーバーがログイン中の本人のIDだけ**を使ってデータを取り出します。URLやAPIのパラメータで他人のIDを指定しても、他人のデータは取れません。
- **管理者用の「他人のデータを見る画面」は作っていません。** 管理者（owner）も、他の利用者のポジション・トレード分析・今日の振り返りは通常の画面では見えません。
- 共通のもの（TOP5・ニュース・イベント・Market Discovery・Radar・システム監視銘柄）は全員同じ。個人のもの（ポジション・トレード分析・反省メモ・今日の振り返り・損益・個人メモ・自分で追加した監視銘柄）は本人だけ。
- 一覧は `docs/admin/data_scope.md` を見てください。

## 1. 利用開始までにやること（初回だけ）

### 1-1. 旧パスワード（平文）の移行 ★重要

以前の `secrets.json` の `"users"`（または環境変数 `APP_USERS`）に平文のパスワードが残っている場合：

1. サーバーを起動します。起動ログに「旧USERSのパスワードをハッシュ化してDBへ移行しました」と出ます。
   （手動で行う場合：`files` フォルダで `python manage_users.py migrate-legacy`）
2. **`secrets.json` の `"users"` を削除**します（平文を残さないため）。
   　Renderの場合は環境変数 `APP_USERS` を削除します。
3. `python manage_users.py list` でownerアカウントがあることを確認します。

### 1-2. 既存の共有データの棚卸し・移行（一度だけ、確認してから）

これまで全員共有だったデータのうち、あなた個人のものを、あなたの個人データにします。

- **トレード反省メモ**：実施済み（1件をownerへ移行、バックアップあり）。
- **監視銘柄**：`python audit_watchlist_shared.py` で棚卸し → 結果は `watchlist_audit_report.txt`。
  　「ownerが手動登録しただけ」の銘柄は、配布**前**に owner 個人へ移してください：
  ```
  python migrate_watchlist_manual_to_owner.py --owner （あなたのユーザー名）           ← 確認だけ（変更なし）
  python migrate_watchlist_manual_to_owner.py --owner （あなたのユーザー名） --apply   ← 実行（バックアップ付き）
  ```
  　移さないままだと、新しい利用者にもあなたの監視銘柄が「共通」として見えてしまいます。

### 1-3. 利用者アカウントを作る

`files` フォルダで実行します（サーバーPC上）。

```
python manage_users.py create user1 --generate
python manage_users.py create user2 --generate
python manage_users.py create user3 --generate
python manage_users.py create user4 --generate
python manage_users.py create user5 --generate
```

- `--generate` を付けると、ランダムな**初期パスワードがその1回だけ**画面に表示されます。**その場で控えてください**（再表示はできません）。
- 自分でパスワードを決めたいときは `--generate` を付けずに実行します（入力は画面に表示されません）。
- ユーザー名は英数字（例：`user1`）。実名にしたい場合は `create tanaka` のように作れます。

### 1-4. URLを決める（利用者に渡すURL）

| 使い方 | URLの例 | 注意 |
|---|---|---|
| クラウド（Render） | `https://（あなたのアプリ名）.onrender.com/` | **HTTPS**で自動的に安全（Cookieに`Secure`が付きます）。おすすめ |
| 自宅のWi-Fiだけ | `http://（サーバーPCのIP）:8765/` | 同じWi-Fiの中だけ。外では使えません。通信は暗号化されません |
| Tailscale（外出先から） | `http://（TailscaleのIP）:8765/` | 仲間内のVPN。利用者全員にTailscaleが必要 |

**インターネットに公開する場合は必ずHTTPS（Render等）にしてください。HTTPのまま公開しないでください。**

### 1-5. 利用者へ渡すもの（この4点だけ）

1. URL
2. ユーザー名
3. 初期パスワード（**URLとは別の連絡手段**で渡すと安全です）
4. 利用者マニュアル（`docs/users/manual_userN.md`、または `python docs/generate_docs.py --html` で作った `.html` をブラウザで開いて「印刷→PDF保存」）

進み具合は `docs/admin/user_setup_checklist.md` に記録します。

## 2. 日常の管理

すべて `files` フォルダで実行します。

| やりたいこと | コマンド |
|---|---|
| 一覧を見る | `python manage_users.py list` |
| 新しい利用者を作る | `python manage_users.py create ユーザー名 --generate` |
| パスワードを変える（忘れた場合も同じ） | `python manage_users.py set-password ユーザー名 --generate`（その人は全端末が自動でログアウトされます） |
| 利用を止める（退会・貸し出し停止） | `python manage_users.py disable ユーザー名`（すぐにログアウトされ、ログインもできなくなります。データは残ります） |
| 利用を再開する | `python manage_users.py enable ユーザー名` |
| 何台でログイン中か | `python manage_users.py sessions ユーザー名` |

### 利用者がログインできないと言われたら

1. `list` で「停止中」になっていないか確認 → 停止中なら `enable`。
2. パスワードを忘れた／わからない → `set-password ユーザー名 --generate` で作り直して、新しいパスワードを渡す。
3. 何度も間違えた場合は**10分**ほどでロックが自動解除されます（サーバーを再起動しても解除されます）。
4. それでもだめなら、URLが正しいか（https/httpの違い、末尾）を確認。

### 自動ログアウトについて

- 7日間まったく使わないと自動でログアウトされます（使っている間は延長されます）。
- ログインしてから最大30日で、必ずログインし直しになります。

## 3. サーバーの再起動・バックアップ・DB確認

### サーバー再起動（自分のPCで動かしている場合）

1. サーバーの黒い画面（コンソール）を閉じる。
2. `start.bat` をダブルクリック。
3. コードを更新したときは、必ずこの再起動が必要です（自動では反映されません）。

Renderの場合は、Renderの画面で「Manual Deploy」または再起動を行います。

### バックアップ

- データは Neon（クラウドのDB）にあります。Neonの管理画面でスナップショット（ブランチ／バックアップ）を取ってください。
- 移行スクリプトは、実行時に `files/backups/` へJSONバックアップを作ります（**このフォルダはGitに入れません**。中身は個人データです）。
- 大きな変更（移行・大量削除）の前は、必ずNeonのバックアップも取ってください。

### DB確認

- 利用者一覧：`python manage_users.py list`
- 個人データが本人にだけ分かれているかの総合確認：下の「4. プライバシー確認テスト」

## 4. 6人のプライバシー確認テスト（必ず実施）

### 4-1. 自動テスト（10〜15分）

`files` フォルダで：

```
python e2e_multiuser_privacy.py
```

- 一時アカウント6人（`e2etmp_` で始まる名前）を自動で作り、実際のログイン・書き込み・読み取り・他人のデータへのアクセス試行までを確認し、終わると一時データを**全て削除**します。
- 結果は `e2e_multiuser_result.txt`。**最後に「全て合格」と出れば合格。1件でも失敗があれば、利用者に渡さないでください。**
- 本物の利用者のデータには触りません。

### 4-2. 手で確認（最初の配布前に一度）

**ポジション**

1. user1でログイン → ポジションを1件登録 → ログアウト
2. user2でログイン → **user1のポジションが見えない**ことを確認 → ログアウト
3. ownerでログイン → user1・user2のポジションが見えないことを確認

**トレード分析／今日の振り返り／反省メモ** も同じ手順で確認します
（user1で作る → user2・ownerで見えないことを確認）。

**共通のもの**：TOP5・ニュース・イベントは、全員同じ内容が見えること。

**監視銘柄**：user1で自分の監視銘柄を1つ追加 → user2・ownerに**出ない**こと。

### 4-3. 確認してはいけないこと

管理者が他の利用者のデータを見るための機能はありません。確認は「見えないこと」の確認だけです。

## 5. セキュリティの決まり

- パスワード：8文字以上。平文は保存されません（PBKDF2＋salt）。
- 連続5回失敗すると、そのユーザー名＋接続元は10分ロックされます。
- Cookie：`HttpOnly`（スクリプトから読めない）／`SameSite=Lax`／HTTPS環境では`Secure`。
- 書き込みAPIはCSRF対策（画面が持つトークン＋同一サイト確認）付き。他のサイトからの操作は拒否されます。
- 他サイトからのAPI呼び出し（CORS）は許可していません（同一サイトのみ）。
- `secrets.json` ・ `files/backups/` ・パスワードは**Gitに入れないでください**（`.gitignore`済み）。
- 共用パソコンで使った利用者には、必ず「ログアウト」を押すよう伝えてください。
- ブラウザ内の一時保存（画面の保存データ）もユーザーごとに分かれています。

## 6. 既知の制約（正直なメモ）

- **利用者本人によるパスワード変更画面は未実装**です（管理者が `set-password` で変更します）。
- **共通監視銘柄をユーザーが「削除」しても、共通のものは消えません**（自分が追加したものだけ削除できます）。
- ENTRY TOP5・場中の一部スキャン（shadow movement／dynamic watch／ENTRY再採点など）は、まだ**ユーザーごとに動きます**。株価・5分足には共通キャッシュがありますが、「利用者が増えても外部APIの呼び出しが増えない」ことの**実測はまだ行っていません**（未確認事項）。Market Discovery（yfinanceスクリーナー＋立花quote確認）だけは**全員で1回だけ**計算するよう修正済みです。
- 6人が同時に重い画面（日次レビュー詳細など）を開くと、遅くなることがあります。
